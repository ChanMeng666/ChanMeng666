# Repo lifecycle and hosting operations

Runbook for everything that happens to a repo or a deployment *after* it has been
built: deciding what stays visible, archiving, making private, deleting, retiring a
hosted site, publishing to npm. State as of **2026-10-03**, after the
2026-10-02/03 cleanup (triage round 2, visibility round 3, add-on shutdown, hosting
and key clean-up).

Operational specifics (droplet, account scopes, token names, backup locations,
closed payment accounts) are deliberately **not** in this public file. They live in
the local-only, gitignored `docs/operations/hosting.private.md` (pattern
`docs/operations/*.private.md` in `.gitignore`). Read it when it exists; never copy
its contents into tracked files. Topology (which repo relates to which) is in
`docs/ecosystem/`; career facts are in `data/profile/`.

## How decisions are made

**Chan decides, the tooling only prepares the question.** Bulk repo decisions are
made on an interactive HTML Artifact generated by `scripts/build-triage-page.mjs`:
every card starts *undecided* (nothing preselected), the script's opinion appears
only as a non-interactive star hint (advisory), and Chan sets each control herself.
Never pre-decide or bundle recommendations into a plan.

Three generator modes (all print a stats summary on stderr; add `--out page.html`,
otherwise HTML goes to stdout; the page is self-contained, no network, so it can be
published as an Artifact):

| Mode | Command | Inputs | Decides |
|---|---|---|---|
| default (project-centric) | `node scripts/build-triage-page.mjs [--repos-json c.json] [--commits-json c30.json] --out triage.html` | live `gh repo list` (or a cached dump via `--dump-repos` / `--repos-json`), `data/profile` | how prominently each catalog project appears on the README |
| `--mode repos` | `node scripts/build-triage-page.mjs --mode repos --repos-json repos.json --commits-full-json commits.json --local-map local-map.json --out triage.html` | `gh repo list` dump, per-repo commit counts, map of repo name to local folder | per live repo: **fate** (keep / shelve / archive / delete) and **visibility** |
| `--mode visibility` | `node scripts/build-triage-page.mjs --mode visibility --repos-json repos-full.json --local-map local-map.json [--portfolio-dir ../2d-portfolio] --out triage.html` | the collector dump (REST fields plus commit, PR, Pages and npm facts) for every repo incl. archived, private, forks and the org allowlist; the working tree is scanned for inbound references | per repo: **archive state** and **public / private** |

Renderers: `scripts/lib/triage-repos-page.mjs` + `triage-repos-client.js`,
`scripts/lib/triage-visibility-page.mjs` + `triage-visibility-client.js`. Run
`node --check` on the client scripts after editing them. Scratch dumps go under
`D:\.claude-scratch\<date>\<slug>\`, never into the repo.

Decisions come back as exported JSON from the page; apply them with `gh`, then
follow the checklists below.

## Checklists

### Archive a repo

1. Disable user-written workflows (`gh workflow disable`), then delete Actions
   secrets, remove webhooks, remove Dependabot config and PRs, clear artifacts and
   caches. Do this **before** archiving: archived repos are read-only.
2. Unpublish GitHub Pages and retire any hosting (see "Retire a deployment").
3. Strip links in all four fact places plus the site (below).
4. `gh repo archive`.
5. Update `docs/ecosystem/lineage.yaml` (or the private overlay) and run
   `npm run check:ecosystem -- --live`.

Settings changes on an already-archived repo need unarchive, change, re-archive;
GitHub can answer 422 right after a state flip, so retry after a short wait.

### Make a repo private

1. Check the repo is not a fork of a public repo (those cannot be made private).
2. Unarchive if needed, flip visibility, re-archive (it stays archived).
3. Strip every link to it from the shards, `cv/`, LinkedIn copy and chanmeng.org:
   **no links to private repos, ever**; evidence is a live site, LinkedIn or a
   package page. Respect in-shard "do not re-add" markers.
4. If an npm package's `repository` field points at it, publish a new version
   without that field (npm provenance is impossible from a private source repo).
5. Stars on the repo drop out of the public count; that was accepted in round 3.
6. Lineage update and `check:ecosystem -- --live`.

### Delete a repo

Delete only after a **second explicit confirmation** from Chan. The `gh` token
needs the `delete_repo` scope (present on this machine). Back up anything local
first, then remove the repo from `lineage.yaml` and every shard.

### Strip links: the four fact places plus the site

A repo or deployment disappearing means checking `data/profile/*.yaml`,
`cv/sections/*.typ`, `70-linkedin.yaml` and `cv/chan-meng-cv-ats.typ`, then the
chanmeng.org repo (`2d-portfolio`). Rebuild (`npm run check`), rebuild the CV PDFs
if a CV changed and sync the site (see `cv/README.md`). `npm run check:links`
finds dead URLs.

### Retire a deployment

Back up first (database exports, bucket contents, config) and store the backup
locally (location in the private file), then delete the project, store or zone.
Retire the DNS and the repo's hosting integration in the same pass. A retired URL
must also disappear from the shards and from `scripts/` helpers that hard-code
URLs (og-covers, screenshot scripts).

### Publish an npm package

Packages: `@chanmeng666/archlang` (the ArchLang compiler), `a11y-loop`,
`@chanmeng666/google-news-server` and `@chanmeng666/google-jobs-server` (repos
`server-google-news` / `server-google-jobs`) and the `chan-meng` CLI, plus side
packages (`@chanmeng666/archlang-mcp`, `@chanmeng666/archlang-font-cjk`,
`vitex-cli`, `@chanmeng666/femtech-radar-mcp`). Publishing needs Chan's **browser
authentication**: prepare the package (version bump, `npm pack --dry-run`), then
Chan runs `npm publish` herself. `chan-meng` 2.0.2 (2026-10-03) was published with
`homepage` https://chanmeng.org and no `repository` / `bugs`, because its source
repo (`chan-meng-cli`) is private and archived. The same was done on 2026-10-03
for `vitex-cli` 0.2.2 (homepage https://www.vitex.org.nz) and
`@chanmeng666/femtech-radar-mcp` 0.4.2. A package whose source repo is private
cannot carry npm provenance; publish it from a local folder
(`npm publish <folder> --access public`). To release from an archived repo:
unarchive, commit, push, re-archive.
